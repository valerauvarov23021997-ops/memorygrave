# DECISIONS.md — Журнал архитектурных решений

> Сюда агент и команда записывают значимые решения:
> что выбрали, почему, какие были альтернативы. Формат ADR (кратко).

---

## ADR-001 · Монорепо на Turborepo
**Контекст:** два приложения (клиент + исполнитель) с общим кодом.
**Решение:** Turborepo + Yarn Workspaces. Общий код в `packages/`.
**Почему:** переиспользование дизайн-системы, типов, API-клиента между приложениями.

## ADR-002 · Мок-режим для разработки без бэкенда
**Контекст:** бэкенд разрабатывается параллельно, UI не должен ждать.
**Решение:** `packages/api` при `USE_MOCKS=true` отдаёт фикстуры из `src/mocks/`.
**Почему:** позволяет собрать и протестировать весь UI до готовности API.

## ADR-003 · Дизайн-концепция Warm Minimal
**Контекст:** чувствительная ниша, аудитория 30–65 лет.
**Решение:** тёплые кремово-зелёные тона, Playfair Display + DM Sans.
**Почему:** транслирует доверие и теплоту, комфортна для старшей аудитории.
Альтернативы (Dark Forest, Stone & Gold) отклонены как менее универсальные.
