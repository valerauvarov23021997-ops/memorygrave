# DECISIONS.md — Журнал архитектурных решений

> Сюда агент и команда записывают значимые решения:
> что выбрали, почему, какие были альтернативы. Формат ADR (кратко).

---

## ADR-001 · Монорепо на Turborepo
**Контекст:** два приложения (клиент + исполнитель) с общим кодом.
**Решение:** Turborepo + Yarn Workspaces. Общий код в `packages/`.
**Почему:** переиспользование дизайн-системы, типов, API-клиента между приложениями.

## ADR-002 · Мок-режим для разработки без бэкенда
**Контекст:** бэкенд разрабатывается параллельно, UI не должен ждать.
**Решение:** `packages/api` при `USE_MOCKS=true` отдаёт фикстуры из `src/mocks/`.
**Почему:** позволяет собрать и протестировать весь UI до готовности API.

## ADR-003 · Дизайн-концепция Warm Minimal
**Контекст:** чувствительная ниша, аудитория 30–65 лет.
**Решение:** тёплые кремово-зелёные тона, Playfair Display + DM Sans.
**Почему:** транслирует доверие и теплоту, комфортна для старшей аудитории.
Альтернативы (Dark Forest, Stone & Gold) отклонены как менее универсальные.

## ADR-004 · Yarn Workspaces без Turborepo
**Контекст:** в окружении сборки платформенные бинарники `@turbo/*` не скачивались
стабильно (обрывы соединения на крупных tarball).
**Решение:** оставили Yarn Workspaces, оркестрацию задач делаем через
`yarn workspaces run <script>`. Turbo убран из зависимостей.
**Почему:** убирает хрупкую зависимость от нативных бинарников, кэш сборки для
проекта такого размера не критичен. Вернуть Turbo можно позже одной строкой.

## ADR-005 · Реестр npm вместо registry.yarnpkg.com
**Контекст:** прокси окружения возвращал «malformed response» для scoped-пакетов
с `registry.yarnpkg.com`, но `registry.npmjs.org` в noProxy (прямой доступ).
**Решение:** `.yarnrc` с `registry "https://registry.npmjs.org/"`.
**Почему:** прямой доступ к npm-реестру стабильнее в этом окружении.

## ADR-006 · Детерминированный formatPrice без ICU
**Контекст:** `Number.toLocaleString('ru-RU')` даёт неразрывный пробел (U+202F)
и зависит от сборки ICU в рантайме.
**Решение:** ручная группировка тысяч обычным пробелом.
**Почему:** предсказуемый вывод и стабильные тесты вне зависимости от устройства.

## ADR-007 · Единый api-слой с встроенным переключателем моков
**Контекст:** нужно разрабатывать UI без бэкенда, но без дублирования кода.
**Решение:** `packages/api/src/endpoints.ts` — каждый метод сам выбирает
мок или реальный axios по `config.useMocks`. Экраны ходят только в этот слой
через React Query, никогда напрямую в axios.
**Почему:** переключение на реальный бэкенд — смена одного флага, UI не трогаем.

## ADR-008 · Яндекс.Карты вместо Google Maps
**Контекст:** приложение используется в регионе, где Яндекс.Карты
привычнее и точнее по кладбищам/адресам, чем Google.
**Решение:** убрали `react-native-maps` (Google/Apple). Превью локации —
компонент `MapPreview`: тап открывает Яндекс.Карты (работает без ключа и в
Expo Go), а при наличии `EXPO_PUBLIC_YANDEX_MAPS_API_KEY` показывает
картинку-миниатюру через Яндекс Static API. Навигация исполнителя — маршрут
в Яндекс.Картах/Навигаторе.
**Почему:** региональная релевантность, отсутствие тяжёлой нативной
зависимости, работа в Expo Go без ключей, простое превью (наша карта
некликабельная — картинка/ссылки достаточно).
