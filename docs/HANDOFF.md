## Как работать с владельцем

- **Общение только на русском.**
- Владелец не разработчик. Любое действие, которое делает он сам, объясняй
  **пошагово**: какую программу открыть, куда нажать, какую команду вставить
  целиком. Он прямо просил об этом — не «выполни миграцию», а «открой
  Supabase → SQL Editor → New query → вставь → Run».
- Компьютер: **Windows**, проект лежит в `C:\Users\Admin\memorygrave`
  (на прошлом компьютере был `C:\Users\user\memorygrave` — в старых
  инструкциях встречается этот путь). Команды давай для `cmd`; если нужен
  PowerShell — так и пиши.
- Не выдумывай цифры. Владелец готовит презентацию инвесторам и прямо просил
  уберечь его от выдуманных чисел. Реальные — в `SUMMARY.md`, раздел 1.
- **Предлагай сам.** Владелец прямо просил: если видишь инструмент, программу
  или способ сделать работу быстрее — предлагай, не жди вопроса. Он не знает,
  что бывает, и рассчитывает на тебя.
- Скажи честно, если ошибся. Однажды серую карту на скриншоте объяснили
  «ограничением веба», а виноват был инструмент съёмки — он это заметил.

## Секреты — правила

- Публичный ключ Supabase (`sb_publishable_…`) публичен по замыслу, он есть
  в `docs/BACKEND.md` и в коде — это нормально.
- **Никогда не проси и не принимай** секретный ключ Supabase (`sb_secret_…`,
  он же service_role) и токен Telegram-бота. Оба однажды утекли в чат и были
  перевыпущены. Они живут только в настройках Supabase.
- `apps/client/.env` в git не попадает (`.gitignore`). Содержимое — в
  `docs/BACKEND.md`, там только публичные значения. Если файл уже есть —
  не перезаписывай его, не посмотрев.

Обновить приложение у тестировщиков:

Обновление отправляет Claude, через Git Bash:

```
cd /c/Users/Admin/memorygrave/apps/client
set -a && . <(tr -d '\r' < .env) && set +a
rm -rf dist && eas update --branch preview --environment preview --message "что изменилось" --non-interactive
grep -c -a pamyatcodebot dist/_expo/static/js/ios/*.hbc   # должно быть 1
```

**Грабли (22.10.2026):** `--environment` обязателен в новых EAS CLI, и с ним
EAS **не читает** локальный `.env`. Без строки `set -a …` обновление молча
уходит на фикстуры: вход «по SMS», код не приходит, Telegram не предлагается.
Поэтому переменные экспортируются в оболочку, а после сборки проверяется,
что имя бота попало в бандл. Если не попало — не считать обновление рабочим.
(Наличие адреса Supabase или ключа в бандле ничего не доказывает: они есть
в коде запасными значениями.)

### SQL — что и в каком порядке

Выполняет **владелец** в Supabase → SQL Editor (у Claude нет прав на DDL —
и не должно быть). Все файлы безопасно запускать повторно.

1. `supabase/setup.sql` — схема, RLS, справочники, демо-данные
2. `supabase/telegram-auth.sql` — коды входа через Telegram
3. `supabase/import-daymische.sql` — съёмка кладбища (382 места)
4. `supabase/import-daymische-names.sql` — ФИО на местах (генерируется, см. ниже)
5. `supabase/executor.sql` — исполнители, этапы заказа, хранилище фотоотчётов

**Добавить исполнителя:** `insert into executors (phone, name) values ('+7…', 'Имя Фамилия');`
Сейчас в списке один — владелец (+79165821650). Приложение исполнителя —
проект Expo `pamyat-executor` (тот же аккаунт), обновления — так же, как у

Файлы 3 и 4 **не правь руками** — они генерируются скриптами из `tools/cemetery/`.

## Инструменты Claude на компьютере владельца

- **Supabase MCP** — прямой доступ к базе (SQL, таблицы, логи, советники).
  SQL теперь выполняет Claude, а не владелец вручную. Изменения схемы
  всё равно согласуй с владельцем до запуска.
- **GitHub CLI** — `%LOCALAPPDATA%\Programs\gh\bin\gh.exe`, вход выполнен.
- **EAS CLI** — установлен глобально (`npm i -g eas-cli`), вход в Expo выполнен
  (`valerchik777`). Обновление у тестировщиков Claude отправляет сам.
- **Автопинг базы** — `.github/workflows/supabase-keepalive.yml`, раз в
  3 дня. Лежит и в `main`: расписание GitHub работает только из ветки по
  умолчанию. Бесплатный проект засыпает через 7 дней без запросов — так
  было с конца августа по 21.10.2026.

## Проверки — что запускать

| Команда | Что проверяет |
|---|---|
| `npm run check` | Типы, ESLint, модульные тесты (utils + поиск по карте). Перед каждым коммитом |
| `e2e/web-smoke.js` | 23 сценария на фикстурах, без окна. Инструкция — `e2e/README.md` |
| `npm run e2e:live` | 10 шагов на **живой базе** в видимом окне Edge, скриншоты и видео в `e2e/out/` |
| `e2e/crawl.js` | Стресс-обход: 16 экранов, каждая кнопка, отчёт `e2e/out/crawl-report.md` (~20 мин) |

Сборки для e2e — с `EXPO_PUBLIC_E2E=1` (без 4-секундного сплэша), сервер —
`node e2e/spa-server.js <папка> <порт>` (прямые адреса экранов). Обходчик не видит
`hitSlop`, поэтому «мелкие кнопки» с расширенной зоной касания — ложные; «Поделиться»
в headless Edge тоже «без реакции» (системное окно не открывается без экрана).

Живой прогон берёт сессию из `e2e/.profile` (вход владельца, в git не попадает).
Перед ним — собрать веб-версию с `.env` в `e2e/dist-live` и поднять сервер на 8098
(команды в шапке `e2e/live-smoke.js`). `HEADLESS=1` — без окна. Сессия истекла —
скрипт ждёт 5 минут, пока владелец войдёт кодом из Telegram.

Нативное приложение на ПК не проверяется: на ноутбуке нет эмулятора Android
(нужен компонент Windows «Платформа низкоуровневой оболочки» — включает владелец).
iPhone с Windows не управляется.

## Грабли, на которые уже наступали

- **Версия SDK = версия Expo Go в магазинах.** Expo Go открывает только свою
  SDK. В октябре 2026 проект переведён с 54 на **57**: у владельца Expo Go 57,
  а Expo Go для SDK 58 в магазинах ещё не было. Прежде чем поднимать SDK —
  узнай версию Expo Go на телефоне владельца.
- **TypeScript 6:** `baseUrl` в tsconfig запрещён, ts-jest требует `rootDir`.
- **После смены SDK — чистая установка:** удалить все `node_modules` и
  `package-lock.json`, затем `npm install`. Иначе в корне остаётся старая
  копия React Native и типы конфликтуют («DimensionValue не подходит к DimensionValue»).

- **МТС LTE душит параллельные TLS-соединения** к Cloudflare (за ним Supabase).
  Поэтому в `packages/api/src/supabase/client.ts` очередь на 4 соединения,
  таймаут 8 с и автомат-размыкатель после 4 таймаутов подряд. Не убирай.
- **Выход из аккаунта не вызывает `signOut()`.** Пользователь анонимный:
  `signOut` уничтожает сессию, и при следующем входе создаётся новый
  пользователь — все сохранённые могилы и заказы теряются.
- **Сменил `.env` — собирай с `--clear`.** Metro кэширует подставленные
  переменные: однажды «живая» сборка молча ушла на фикстуры. Проверка —
  в подвале профиля пишется режим: `mocks` или `supabase`.
- **Яндекс-шлюз:** обычная HTTP-интеграция ломает заголовки и шлёт метод `ANY`
  буквально (ошибка 501). Поэтому прокси — Cloud Function, а не HTTP-интеграция.
- **Номер 125 на плане в стороне** — это условное обозначение из легенды
  чертежа, а не могила. `export_app.py` отсекает такие объекты автоматически.

## Кладбище д. Даймище

Исходник — DWG от геодезиста, система координат МСК-47 зона 2. Подробности
пересчёта и проверки — `tools/cemetery/README.md`. Сам DWG в репозитории не
хранится — оригинал у владельца.

| Скрипт | Что делает |
|---|---|
| `extract.py` | DXF → `docs/cemetery/cemetery.json` |
| `to_wgs84.py` | Пересчёт в WGS-84 → `docs/cemetery/cemetery-wgs84.geojson` |
| `render_plan.py`, `build_pdf.py` | План кладбища в SVG и PDF |
| `export_app.py` | GeoJSON → `supabase/import-daymische.sql` + мок для демо-режима |
| `import_names.py` | Ведомость CSV → `supabase/import-daymische-names.sql` |

Python-зависимости: `pip install pyproj ezdxf`.

На компьютере владельца Python 3.12 стоит в
`%LOCALAPPDATA%\Programs\Python\Python312\python.exe`. В PowerShell перед
запуском скриптов задай `$env:PYTHONIOENCODING = "utf-8"` — иначе русский
вывод скриптов падает на кодировке консоли. `winget` на этом компьютере нет. Для чтения DWG нужен
LibreDWG (`dwg2dxf`) — на Windows проще попросить у геодезиста DXF.

рядом со строками — `photos/проверка.html` (локально, не в git).

результат даёт локальный `supabase/import-daymische-names.sql` (повторный запуск безопасен).

**Фото памятников** (22.10.2026): у всех 375 человек 1–4 снимка, крупный план

## Sentry — подключён 22.10.2026

Организация **memorygrave.sentry.io**, проект **pamyat-client** (сервер в США,
`ingest.us.sentry.io`). DSN — в `apps/client/.env` (`EXPO_PUBLIC_SENTRY_DSN`),
он публичный. Auth Token в чате **не принимать** — это секрет.

Проверено 22.10.2026: тестовое событие с ПК владельца принято (HTTP 200);
веб-сборка отправила необработанную ошибку (envelope → 200); обновление
`eas update` с DSN выпущено на ветку preview. Ошибки различаются по
`environment`: `supabase` — боевые, `mocks` — демо, `test` — проверка связи.

С iPhone владельца (Россия) событие тоже дошло — проверено 22.10.2026 временной
кнопкой, потом убранной (PAMYAT-CLIENT-2). Если Sentry когда-нибудь заблокируют —
запасной вариант GlitchTip (тот же протокол).

Sentry MCP подключён (22.10.2026, `claude mcp add --transport http sentry https://mcp.sentry.dev/mcp`,
локально для проекта; вход владелец сделал через `/mcp` → sentry → Authenticate).
Claude читает ошибки сам: организация `memorygrave`, проект `pamyat-client`,
regionUrl `https://us.sentry.io`. Новый сервер виден только после перезапуска
Claude Code (`claude --continue`).

Экран владельца Claude видит снимком через PowerShell (System.Drawing),
окна выводит вперёд через user32 SetForegroundWindow; кликать за владельца не может.
