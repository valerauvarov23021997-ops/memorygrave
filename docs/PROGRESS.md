## ✅ Проверки пройдены

Зависимости ставились через **npm** (`registry.yarnpkg.com` за прокси
отдавал «malformed response» для scoped-пакетов; npmjs.org — прямой доступ,
стабильно). В репозитории есть `package-lock.json`.

Прогнано и **успешно**:
- Типизация `tsc --noEmit` по всем 6 модулям (utils, api, store, ui,
  client, executor) — **0 ошибок** ✅
- `packages/utils` — **16 unit-тестов** проходят (`jest`) ✅
- Сборка JS-бандла клиента: `expo export` → **App exported**, Hermes-бандл
  ~9.95 MB, все ассеты выгружены ✅
- Сборка JS-бандла исполнителя: `expo export` → **App exported** ✅

Что это значит: оба приложения полностью собираются Metro — все импорты
резолвятся, babel/reanimated работает, JSX компилируется. Запуск на телефоне
(Expo Go) или в эмуляторе делается командой `npm run client` / `npm run executor`
в окружении с UI-устройством.

### Правки, найденные при проверках (см. коммиты)
- Веса шрифтов: пакеты `@expo-google-fonts/*` не содержат `300 Light` —
  заменено на `400 Regular` в токенах и загрузчике шрифтов.
- `react-native-maps` не поставляет config-plugin в 1.14 — ключ Google Maps
  перенесён в `ios.config` / `android.config.googleMaps`.
- Metro monorepo: убран `disableHierarchicalLookup` (при npm-раскладке
  `@react-native/virtualized-lists` вложен в `react-native/node_modules`).
- i18n: параметр-строка переименован из `count` (зарезервирован под число) в `value`.
- Компонент `Icon`: тип `name` расширен до строки (иконки услуг приходят из API).

Мок-режим включён по умолчанию (`EXPO_PUBLIC_USE_MOCKS` != 'false'),
поэтому оба приложения работают без бэкенда.

## Журнал задач

### 00 · Setup — `DONE`
Монорепо (Yarn Workspaces), tsconfig strict, prettier, `.yarnrc` (npm-реестр).
Пакеты `utils`, `api`, `store`, `ui`. Токены дизайн-системы, axios-клиент с
refresh-логикой, мок-режим с фикстурами, конфиги Expo для двух приложений.
Turbo убран (см. ADR-004), задачи — через `yarn workspaces run`.

### 01 · Design System — `DONE`
15 компонентов: Button, Input, Card, TopBar, Badge, SectionLabel, Divider,
Avatar, Toggle, StarRating, Skeleton, BottomSheet, Chip, Icon, Text.
ToastProvider + useToast. Все цвета/шрифты — только из токенов.

### 02 · Auth — `DONE`
Онбординг (3 слайда, FlatList paging), ввод телефона с маской, экран SMS
(6 ячеек, таймер, автосабмит). Хранение токенов в SecureStore, гейт в `index`.

### 03 · Search — `DONE`
Экран поиска: пустое состояние, скелетоны, результаты, фильтр-чипы,
карточка «Добавить захоронение». Экран добавления с BottomSheet выбора кладбища.

### 04 · Grave — `DONE`
Страница захоронения: карта (react-native-maps), биография с раскрытием,
действия (фото/сохранить/напомнить), избранное, блок последнего заказа,
липкая кнопка «Заказать уход».

### 05 · Catalog — `DONE`
Каталог услуг (быстрые/крупные), BottomSheet деталей услуги,
форма заказа: выбор даты (14 дней), повтор, пожелания, итог.

### 06 · Orders — `DONE`
Оплата (ЮКасса-заглушка, создание заказа), список заказов с фильтрами и
pull-to-refresh, экран статуса с анимированным таймлайном из 5 шагов.

### 07 · Reports — `DONE`
Фотоотчёт: сетки «до»/«после», оценка звёздами с автосохранением (debounce 800мс),
кнопки повторного заказа и скачивания.

### 08 · Reminders — `DONE`
Памятные даты с переключателями, расчёт «через N дней», блок автозаказа к дате.

### 09 · Profile — `DONE`
Профиль с баннером подписки (градиент), разделы «Моё»/«Помощь», выход.
Экран подписки: 3 тарифа, выделенный «Стандарт», восстановление покупок.

### 10 · Executor — `DONE`
Отдельное приложение `apps/executor`: вход, вкладки (Заказы/История/Профиль),
активные заказы с принять/отклонить, экран выполнения (степпер:
детали → навигатор → фото до → чек-лист → фото после → завершение,
обязательные 2+ фото), профиль с онлайн/офлайн и статистикой.

### 11 · Notifications — `IN PROGRESS`
`lib/notifications.ts`: запрос прав, регистрация push-токена, обработчик.
Полноценные push и deeplinks требуют реальных ключей FCM/APNs.

### 12 · Backend (Supabase) — `DONE` · 2026-07-05
Реальный бэкенд: схема Postgres с RLS (`supabase/setup.sql` — таблицы,
триггер профиля, RPC свечей, сиды), адаптер `packages/api/src/supabase/`
с теми же интерфейсами, что моки/REST, переключатель режимов в `config.ts`
(`mocks` / `supabase` / `rest`). На реальной базе: авторизация, захоронения,
избранное, заказы, свечи, воспоминания, напоминания, профиль, уведомления.
На моках до фазы 2: оплата (ЮКасса), приложение исполнителя, SMS-код.
Инструкция запуска — `docs/BACKEND.md`.

### Имена с памятников Даймища — `DONE` · 2026-10-21
723 фото памятников → ведомость `docs/cemetery/daymische-names.csv` (437 строк).
Расшифровка параллельно по диапазонам номеров; места, где чтение шло не по
фото, перепрочитаны независимо — ФИО и даты совпали. В базе 375 человек на
344 местах. На памятниках часто только год — новые колонки `graves.birth_year`
/ `death_year`, приложение показывает год, когда полной даты нет (напоминания
по году не ставятся). Не внесены: 7 частично прочитанных ФИО, 9 могил вне плана.

### Исполнитель на боевой базе + фотоотчёты — `DONE` · 2026-10-22
Таблица `executors` (вход по телефону из списка + код Telegram), этапы заказа —
только через функции базы (взять → на месте → фото до/после → завершить; без
2+2 фото не закрыть). Фото — закрытое хранилище `reports`, клиент видит их по
временным ссылкам; посторонний — нет (проверено). Сквозная проверка в веб-версии
на живой базе с тестовыми аккаунтами, затем удалены. Проект Expo `pamyat-executor`.

### Доводка перед показом — `DONE` · 2026-10-23
- База: служебные функции закрыты от вызова извне, журнал диагностики — только
  свой, правила доступа считают `auth.uid()` один раз, индексы под внешние ключи
  (`supabase/hardening.sql`).
- Карта: оградки отдельным слоем `cemetery_plots` — все 266 (две были без номеров внутри).
- Удаление аккаунта: кнопка в профиле, удаляет база (`supabase/account.sql`).
- Оплата: без ЮКассы заказ оформляется «оплата после фотоотчёта», платные
  тарифы — «Скоро» (ADR-010). Демо-кладбища убраны из боевой базы (`demo-seed.sql`).
- Исполнитель: отказы помнятся после перезапуска, Sentry с тегом `app=executor`.
- Демо-режим: новый заказ находится на экране статуса, у статуса есть ошибка.
