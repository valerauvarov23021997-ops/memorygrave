# 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

## 1.1 Цель и назначение
«Память» — мобильное приложение (iOS + Android) для двух задач:
Цифровой реестр захоронений — возможность найти могилу по имени, кладбищу, городу и просмотреть страницу памяти с фото и биографией.
Маркетплейс услуг ухода — заказ уборки, цветов, надгробных плит, скамеек, оград и других услуг с фотоотчётом после каждого выполнения.
Целевая аудитория — люди, чьи родственники похоронены в другом городе или регионе, и у них нет возможности приехать лично. Ключевая ценность: спокойствие и уверенность, что о могиле близкого человека заботятся.

# 3. КЛИЕНТСКОЕ ПРИЛОЖЕНИЕ — ЭКРАНЫ И ФУНКЦИОНАЛЬНОСТЬ

## 3.1 Авторизация

### 3.1.1 OnboardingScreen
Показывается только при первом запуске (флаг в AsyncStorage).

### 3.1.2 PhoneInputScreen
Поле ввода номера телефона с маской +7 (___) ___-__-__
Кнопка "Получить код" — активна только при заполненном номере (11 цифр)
Кнопки Apple Sign-In и Google Sign-In под основной формой
При нажатии: API POST /auth/send-code → переход на SmsCodeScreen
Ошибки: "Некорректный номер", "Ошибка отправки, попробуйте позже"

### 3.1.3 SmsCodeScreen
6 отдельных полей ввода (автофокус следующего при заполнении)
Таймер обратного отсчёта 60 сек. После — кнопка "Отправить повторно"
При заполнении всех 6 цифр: автоматический вызов API POST /auth/verify-code
Успех: сохранение JWT в SecureStore → переход в Main Stack
Ошибка: "Неверный код", поля очищаются
Автоматическое считывание SMS через SMS Retriever API (Android) и подтверждение через Messages (iOS 12+)

## 3.2 Поиск захоронений (SearchScreen)
Главный экран приложения (первая вкладка в Bottom Tab Navigator).

### 3.2.1 Поисковая строка
Поиск по: ФИО, кладбище, город
Минимум 2 символа для начала поиска
Debounce 400 мс — запрос не отправляется при каждом нажатии
API GET /graves/search?q=&city=&cemetery=&page=&limit=20
Состояния: loading skeleton, пустой результат, список результатов

### 3.2.2 Фильтры
Город — выпадающий список из API
Кладбище — зависит от выбранного города
Сброс фильтров — кнопка "Очистить"
Фильтры сохраняются в сессии (не в хранилище)

### 3.2.3 Карточка результата
ФИО, годы жизни, кладбище и участок
Статус-бейдж: "Оцифровано" (зелёный) / "На модерации" (жёлтый)
Нажатие → GraveScreen

### 3.2.4 Добавление захоронения
Кнопка "Не нашли? Добавить захоронение" внизу экрана при 0 результатах или всегда
Открывает форму: ФИО, дата рождения, дата смерти, кладбище (выбор из списка), участок/ряд, фото (опционально), краткая биография (опционально)
После отправки: статус "На модерации", уведомление по готовности

## 3.3 Страница захоронения (GraveScreen)

### 3.3.1 Структура экрана (ScrollView)
Мини-карта (Google Maps) с маркером на точном участке. Нажатие → открывает навигатор (deeplink в Google Maps / Яндекс Навигатор).
Блок данных: ФИО (крупно), даты жизни, кладбище, участок/ряд.
Биография (опционально). Текст с "читать полностью" при >3 строках.
Фотогалерея: горизонтальный скролл, нажатие → полноэкранный просмотр.
Блок действий: кнопки "Сохранить в избранное", "Поделиться", "Напомнить о дате".
История заказов по этой могиле (последние 3).
Большая кнопка "Заказать уход" → OrderScreen.

### 3.3.2 Логика сохранения в избранное
POST /user/saved-graves + graveId
Иконка сердца в хедере меняется на заполненную
Появляется в SavedGravesScreen
Удаление: DELETE /user/saved-graves/:graveId

### 3.3.3 Поделиться
Share API → текст: "Страница памяти: [ФИО], [кладбище]"
В MVP без ссылки на веб-страницу — только текст

## 3.5 Оплата (PaymentScreen)
Методы оплаты: банковская карта (ввод вручную), СБП (по номеру телефона), Apple Pay (iOS), Google Pay (Android)
Сохранение карты: опция "Запомнить карту" → токенизация через ЮКасса/Stripe, CVV не хранится
После успешной оплаты: экран "Заказ принят" с деталями и кнопкой "В мои заказы"
После провала оплаты: сообщение об ошибке, возможность повторить
Email-квитанция: POST /payments/receipt → письмо на email пользователя

## 3.8 Памятные даты и автозаказ (RemindersScreen)

### 3.8.1 Управление датами
Автозаполнение из реестра: день рождения и годовщина смерти (если есть)
Добавление произвольной даты (название + дата)
Удаление и редактирование дат

### 3.8.2 Напоминания
Push-уведомление за 7 дней и за 3 дня до каждой даты
Пользователь выбирает: напоминать / не напоминать для каждой даты отдельно
При нажатии на уведомление → открывается GraveScreen соответствующей могилы

### 3.8.3 Автозаказ
Пользователь выбирает услуги из каталога + привязанный метод оплаты
Выбирает за сколько дней до даты выполнять (1, 3, 5, 7 дней)
Подтверждение автозаказа приходит push-уведомлением, пользователь может отменить в течение 24 часов
Требует подписку Standard или Premium
⚠ Автозаказ — ключевая функция удержания. Пользователь, настроивший автозаказ, практически не уходит.

# 4. ПРИЛОЖЕНИЕ ИСПОЛНИТЕЛЯ

## 4.1 Авторизация исполнителя
Вход по номеру телефона + SMS (аналогично клиентскому)
Аккаунт исполнителя создаётся администратором в панели управления
При первом входе — обязательное заполнение профиля и прохождение верификации

## 4.2 Профиль исполнителя
ФИО, фото, телефон
Города и кладбища — где работает (выбор из списка)
Типы услуг — что умеет выполнять (мультивыбор)
Документы для верификации: фото паспорта (загрузка через приложение)
Переключатель "Онлайн / Офлайн" — получать новые заказы или нет
Рейтинг и статистика (только просмотр)

## 4.3 Входящие заказы (ActiveOrdersScreen)
Список заказов, назначенных этому исполнителю
Карточка: услуга, кладбище + участок, дата и время, сумма вознаграждения
Push-уведомление при назначении нового заказа
Кнопки: "Принять" / "Отклонить" (с указанием причины)
При отклонении — заказ возвращается в очередь, другому исполнителю

## 4.4 Выполнение заказа (ExecutionScreen)
Последовательность экранов при выполнении:
Детали заказа: адрес кладбища, участок/ряд, описание услуги, пожелания клиента
Кнопка "Открыть в навигаторе" → deeplink в Google Maps / Яндекс Навигатор
Кнопка "Я на месте" → статус меняется на "Исполнитель на месте"
Фото ДО: обязательная загрузка минимум 2 фотографий текущего состояния
Чек-лист работ: перечень действий для данной услуги (тики по мере выполнения)
Фото ПОСЛЕ: обязательная загрузка минимум 2 фотографий результата
Кнопка "Завершить заказ" → статус "Выполнен", клиент получает push с отчётом
⚠ Фото ДО и ПОСЛЕ — обязательные шаги. Без загрузки фото невозможно нажать "Завершить заказ". Это критично для доверия пользователей.

## 4.5 История заказов исполнителя
Список завершённых заказов с датами и суммами
Фильтр по периоду: неделя / месяц / произвольный

# 8. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

## 8.1 Производительность
Время запуска (cold start): не более 3 сек на среднем смартфоне (2 ГБ RAM)
Время ответа API: не более 2 сек для 95% запросов
Поиск: результаты должны появляться не позднее 500 мс после прекращения ввода
Загрузка фото: оптимизация до отправки на сервер (max 1 МБ на фото, WebP)
FlatList для длинных списков (виртуализация)
Изображения: кеширование через react-native-fast-image

## 8.2 Безопасность
JWT-токены: accessToken (15 мин), refreshToken (30 дней) в SecureStore
Biometric Auth: Touch ID / Face ID для повторного входа (опционально, P2)
Данные карт: не хранятся в приложении, только токены платёжного шлюза
SSL Pinning для продакшн-среды
Обфускация кода (Hermes + ProGuard для Android)
Запрет скриншотов на экранах оплаты (Android: FLAG_SECURE)

## 8.3 Оффлайн-поведение
Главный экран поиска — загружается из кеша при отсутствии сети
Сохранённые могилы — доступны оффлайн
Заказы и оплата — только онлайн, при отсутствии сети: баннер "Нет подключения"
Очередь действий: если действие (например, "сохранить могилу") не выполнено из-за сети — повтор при восстановлении

## 8.4 Доступность (Accessibility)
accessibilityLabel на всех интерактивных элементах
Минимальный размер touch-target: 44×44 pt
Поддержка Dynamic Type (iOS) и Font Scale (Android) — базовый уровень
Контраст текста: минимум WCAG AA (4.5:1)
