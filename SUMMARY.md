### Что это значит для презентации

**Можно говорить:** одно кладбище оцифровано полностью, 382 места с точностью
1–3 м, работающее приложение поверх этих данных, живой бэкенд.

**Нельзя говорить:** про пользователей, заказы, выручку, retention, LTV,
«N кладбищ в работе». Ничего этого нет. Продукт находится в стадии
**работающего прототипа с одним реальным набором данных** — это честная и
вполне нормальная стадия для pre-seed, но выдавать её за traction нельзя.

### Про людей в базе

**375 реальных людей** на 344 из 382 мест Даймища — переписаны с фотографий
памятников (723 фото, август 2026). Остальные места — безымянные кресты, пустые
таблички или могил по факту нет. 7 надписей прочитаны не полностью и в базу пока
не внесены; 9 человек лежат в могилах, которых нет на плане геодезиста, — тоже
не внесены. Порядок номеров внутри общих оградок условный (слева направо), не сверен.

Придуманных людей в боевой базе больше нет. Демо-режим приложения (фикстуры)

## 3. Что работает по-настоящему

Проверено запросами к боевой базе и прогоном сценариев в браузере.

**Инфраструктура**
- Postgres (Supabase, Frankfurt) с построчной защитой доступа (RLS) на всех таблицах
- Анонимная авторизация: пользователь получает данные сразу, до ввода телефона
- Вход по коду **через Telegram-бота** вместо платных SMS (0 ₽ за код)
- Резервный канал в Россию: Yandex Cloud API Gateway + Cloud Function перед Supabase
- Обновления «по воздуху» через EAS Update — новая версия у тестировщиков без пересборки

**Данные кладбища** (это главный актив)
- DWG-съёмка геодезиста разобрана в геометрию
- Координаты пересчитаны МСК-47 зона 2 → WGS-84, проверены тремя способами
- Многостраничный план в PDF — `docs/cemetery/cemetery-plan.pdf`
- GeoJSON для внешних систем — `docs/cemetery/cemetery-wgs84.geojson`
- Пересборка данных одной командой: `python3 tools/cemetery/export_app.py`

**Функции приложения**
- Поиск человека по имени, городу, кладбищу
- Карточка памяти: биография, фотогалерея, карта, участок
- Карта кладбища: план, поиск по фамилии и номеру, ФИО на местах, пеший маршрут в Яндекс.Картах
- Фото памятников в карточках у всех 375 человек Даймища
- Свеча памяти — горит 24 часа, состояние общее для всех
- Книга воспоминаний — записи от родственников
- Сохранённые могилы, приглашение родственников, QR-код
- Памятные даты с локальными напоминаниями
- Создание заказа с выбором услуги, даты и повтора
- Список и статусы заказов

## 4. Что не подключено — прямым текстом

### Оплата — выключена честно

Без юрлица и договора с ЮКассой принимать деньги нельзя. До 23.10.2026 экран
оплаты показывал «Оплата прошла успешно», хотя ничего не списывалось. Теперь
заказ оформляется с пометкой «Платить сейчас не нужно — оплата после выполнения,
когда вы увидите фотоотчёт», первый шаг статуса — «Оформлен» (ADR-010).

Код под ЮКассу остался: включается переменной `EXPO_PUBLIC_PAYMENTS=true`,
когда появится договор и серверная часть для подтверждения платежа (webhook).

### Приложение исполнителя и фотоотчёты — работают с 22.10.2026

Исполнитель входит кодом из Telegram, если его телефон есть в таблице
`executors` (добавляет владелец). Видит свободные заказы, берёт заказ, отмечает
«на месте», снимает фото до и после, закрывает заказ — без 2+2 фото база
закрыть не даст. Фото — в закрытом хранилище `reports`: видят только заказчик
и исполнитель. Клиент получает уведомления на каждом этапе (в приложении, не push).
Вознаграждение — 80% стоимости (решение владельца). Схема — `supabase/executor.sql`.
Не сделано: расстояние до кладбища. Отказ от заказа помнится на телефоне исполнителя.

### Push-уведомления — только каркас

`apps/client/src/lib/notifications.ts`: права запрашиваются, токен получается,
обработчик стоит. Отправлять некому — нет ключей APNs/FCM и серверной отправки.
Владелец вступает в Apple Developer Program (10.2026). Памятные даты работают
через **локальные** уведомления телефона — они реальные, но живут только на устройстве.

### Подписка — без покупок

Три тарифа видны, платные помечены «Скоро» — по той же причине, что и оплата.
Все пользователи на «Базовом».

### Удаление аккаунта — есть

Кнопка в профиле. Удаляет база (`supabase/account.sql`): пользователя и всё
личное — заказы, сохранённые, даты, воспоминания. Страницы памяти, которые
человек добавил, остаются для родственников. Требование App Store и 152-ФЗ.

### База засыпает — решено

Бесплатный проект Supabase засыпает после 7 дней без запросов (так было с конца
августа по 21.10.2026). С 21.10.2026 его раз в 3 дня будит GitHub Actions.

## 5. Технический состав

```
Строк кода          ~14 000 (TypeScript/TSX, без фикстур и node_modules)
Коммитов            138
Период разработки   1 июля — 23 октября 2026
```

**Стек:** React Native 0.88 + Expo SDK 58 (с 29.10.2026), TypeScript strict,
Expo Router, Zustand, TanStack Query, Reanimated 4, react-native-svg,
i18next, Supabase (Postgres + Auth + Edge Functions), Yandex Cloud.

**Структура:**

```
apps/client      клиентское приложение (21 экран)
apps/executor    приложение исполнителя (6 экранов, на боевой базе)
packages/ui      дизайн-система: 21 компонент, токены, тема
packages/api     API-клиент: 13 групп, три режима (mocks/supabase/rest)
packages/store   состояние (Zustand)
packages/utils   форматирование, валидация, даты
tools/cemetery   обработка съёмки: DWG → координаты → SQL, план, PDF
supabase         схема БД, RLS, RPC, Edge Functions, импорт съёмки
```

**Качество:** `tsc --noEmit` и ESLint без ошибок, 54 модульных теста
(с 21 по 29.10.2026 14 тестов клиента не запускались — починено при переходе на SDK 58). Сквозные
автотесты в браузере: 23 сценария на фикстурах, 10 шагов на живой базе, обход
всех кнопок 16 экранов (`e2e/`). Ошибки с телефонов — в Sentry (оба приложения).

## 6. Ближайшие шаги по убыванию ценности

1. **Второе и третье кладбище.** Один оцифрованный объект — это демонстрация,
   три — это уже метод, который можно масштабировать и показывать инвестору.
2. **Юрлицо и ЮКасса.** Пока нет — нет ни одного платящего клиента,
   а значит и никакой unit-экономики.
3. **Push-уведомления** (APNs/FCM) — нужны для возврата пользователя. Ждём Apple.
4. **Сверка на месте в Даймище:** 7 неполных ФИО, 9 могил вне плана, порядок
   номеров в общих оградках.

## 7. Как показать продукт вживую

**Телефон:** Expo Go → QR-код ветки `preview`. Тестировщику нужен аккаунт
Expo и приглашение в организацию (роль Viewer).

**Скриншоты:** `docs/screenshots/` — 15 экранов, сняты 11.08.2026 с боевой
базы, не макеты (до 23.10.2026: на некоторых видны демо-кладбища, которых в базе уже нет). В подвале профиля виден режим сборки `supabase` — это
подтверждение, что данные настоящие. Для съёмки экрана «Сохранённые» в
избранное были добавлены три демо-персоны; заказы намеренно не создавались,
чтобы не искажать отчётность.

Карта на карточке памяти — статичная плитка Яндекс.Карт с меткой участка,
тап открывает Яндекс.Карты. Ключ клиентский, лежит в `MapPreview.tsx`.

**Данные кладбища для проверки:** `docs/cemetery/cemetery-plan.pdf` —
план на 5 листах A3, который можно показать заказчику или администрации
кладбища.
