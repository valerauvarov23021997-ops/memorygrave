## 📋 О проекте

**Память** — приложение для поиска захоронений и заказа услуг по уходу за могилами
(уборка, цветы, надгробные плиты, скамейки) с обязательным фотоотчётом.
Целевая аудитория: люди 30–65 лет, чьи близкие похоронены в другом городе.

Два приложения на одной кодовой базе:
- **Клиентское** (`apps/client`) — поиск, заказ услуг, оплата, отчёты, памятные даты
- **Исполнительское** (`apps/executor`) — приём заказов, выполнение, загрузка фото

Эмоция продукта: **доверие, теплота, спокойствие**. Не холодный сервис.

## 🚦 Как работать — рабочий цикл

Ты работаешь **итеративно, по одной задаче за раз**:

1. **Открой `docs/PROGRESS.md`** — найди первую задачу со статусом `TODO`.
2. **Прочитай файл задачи** целиком (`tasks/NN-*.md`).
3. **Прочитай зависимости** — задачи выполняются строго по порядку (00 → 11).
4. **Реализуй** задачу согласно описанию. Пиши реальный рабочий код.
5. **Проверь себя** по чеклисту в конце файла задачи.
6. **Прогони проверки** (см. раздел «Проверки» ниже).
7. **Обнови `docs/PROGRESS.md`** — отметь задачу `DONE`, впиши дату и краткое резюме.
8. **Сделай коммит** с понятным сообщением (см. «Git»).
9. Переходи к следующей задаче.

> Не берись за задачу N+1, пока N не отмечена `DONE` и проверки не проходят.
> Если задача большая — разбей на подзадачи внутри неё, но не пропускай порядок.

## 📐 Правила написания кода — ОБЯЗАТЕЛЬНЫ

- **TypeScript strict.** Никаких `any`. Все типы явные.
- **Только функциональные компоненты.** Никаких классовых.
- **Стили — только `StyleSheet.create()`.** Никаких inline-объектов в JSX.
- **Цвета и шрифты — только из токенов** `@pamyat/ui`. Никакого хардкода HEX.
- **Строки UI — через i18n** (`i18next`), даже если сейчас только русский.
- **Touch target — минимум 44×44pt** для всех нажимаемых элементов.
- **Изображения — `expo-image`**, не `Image` из core.
- **Анимации — `react-native-reanimated` v3**, не `Animated` из core.
- **Ошибки — `try/catch`** для всех async + `Sentry.captureException`.
- **Импорты пакетов** — через алиасы `@pamyat/ui`, `@pamyat/api`, `@pamyat/store`, `@pamyat/utils`.
- **Комментарии** — только на русском и только там, где нужно объяснить «почему», не «что».
- **Именование файлов** — компоненты `PascalCase.tsx`, утилиты `camelCase.ts`.

## 🔌 API (кратко — полностью в `docs/API.md`)

```
Base URL: https://api.pamyat.app/v1
Auth:     Authorization: Bearer <accessToken>   (все эндпоинты кроме /auth/*)
Формат:   { data: T, error: string | null, meta?: { total, page, limit } }
```

Пока бэкенд не готов — используй **мок-режим**: `packages/api` отдаёт фикстуры из
`packages/api/src/mocks/`. Переключатель — переменная окружения `USE_MOCKS=true`.
Это позволяет разрабатывать UI не дожидаясь бэкенда.

## 🌱 Git — правила коммитов

Формат сообщения: `тип(область): описание`

```
feat(auth): экран ввода телефона и SMS-кода
feat(ui): компоненты Button, Input, Card
fix(search): исправлен debounce поиска
chore(setup): инициализация Expo-проекта
```

Один коммит = одна логически завершённая часть. Коммить часто.
После завершения задачи целиком — коммит `feat(taskNN): краткое описание` + обнови PROGRESS.md.

## ⚠️ Важные принципы

- **Не выдумывай API-эндпоинты** — используй только те, что в `docs/API.md`. Если чего-то не хватает — добавь в `docs/API.md` с пометкой `// TODO: согласовать с бэкендом` и используй мок.
- **Не пропускай состояния экранов** — для каждого экрана нужны loading (Skeleton), empty, error, success.
- **Не используй заглушки Lorem Ipsum** — только реалистичные русские данные (имена, кладбища, суммы).
- **Спрашивай, только если задача действительно неоднозначна.** Иначе — принимай разумное решение, фиксируй его в комментарии и в `docs/DECISIONS.md`, продолжай.
- **Если застрял** — не удаляй чужой код. Опиши проблему в `docs/PROGRESS.md` в разделе задачи и переходи к тому, что можешь сделать.

## 📞 Когда остановиться и спросить

Останавливайся и задавай вопрос человеку только в этих случаях:
1. Нужны секретные ключи/токены (API-ключи, credentials) — их у тебя нет.
2. Задача противоречит уже написанному коду или другой задаче.
3. Требуется решение, влияющее на деньги/юридические аспекты (условия оплаты, договор оферты).

Во всех остальных случаях — действуй автономно по задачам.
