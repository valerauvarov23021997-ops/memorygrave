# Разбор геодезической съёмки кладбища

Исходник от геодезиста — DWG (AutoCAD 2018), система координат **GS47Z2**.
Расшифровано: это **МСК-47 зона 2** (Ленинградская область), параметры
взяты из открытого каталога geobridge.ru:

```
+proj=tmerc +lat_0=0 +lon_0=30.95 +k=1 +x_0=2250000 +y_0=-6211057.628
+ellps=krass +towgs84=23.57,-140.95,-79.8,0,0.35,0.79,-0.22 +units=m
```

Кладбище находится в **д. Даймище, Гатчинский район** — 59.3180, 29.8760.

### Как проверялась привязка

1. **Масштаб.** По 359 парам съёмочных точек сравнили плоские расстояния
   с геодезическими: систематическое искажение −48,2 ppm при разбросе
   0,2 ppm. Это в точности расчётный масштабный коэффициент проекции на
   удалении 61 км от осевого меридиана — геометрия перенеслась жёстко.
2. **Дороги.** Асфальт из съёмки лёг на дорогу 41К-475 из OpenStreetMap:
   минимальное расстояние 0,1 м, среднее 12 м (это полуширина дороги —
   мы обвели края, в OSM осевая линия).
3. **Визуально.** `docs/cemetery/verify.png` — план поверх карты OSM.

Контур кладбища в OSM (`landuse=cemetery`, обведён по снимку Bing) смещён
относительно наших данных примерно на 150 м. Верны наши: дороги совпали.
Абсолютная точность ограничена датум-сдвигом СК-42→WGS-84 (~1–3 м), для
навигации к могиле этого достаточно — GPS телефона даёт ±5 м.

| Слой | Содержимое |

| `ДОРОГА АСФ` / `ЩЕБЕНЬ` / `ГРУНТОВАЯ ДОРОГА` | дорожная сеть |

Территория участков — 152 × 175 м. ФИО в съёмке **нет**, только номера:
нужна ведомость захоронений «номер → ФИО → даты».

## Как повторить разбор

DWG 2018 не читается напрямую ни ezdxf, ни GDAL. Нужен конвертер LibreDWG
(в apt-репозиториях Ubuntu его нет — собирается из исходников):

```bash
git clone --depth 1 https://github.com/LibreDWG/libredwg.git
cd libredwg && sh autogen.sh && ./configure --disable-bindings --disable-docs --enable-release && make -j4
LD_LIBRARY_PATH=src/.libs programs/dwg2dxf -o cemetery.dxf исходник.dwg
```

Дальше (нужны `ezdxf`, `pyproj`):

```bash
python3 extract.py       # DXF → cemetery.json (участки, номера, дороги, точки)
python3 to_wgs84.py      # → cemetery-wgs84.geojson + graves-wgs84.json
python3 render_plan.py   # → plan-overview.svg + plan-{А,Б,В,Г}.svg
python3 build_pdf.py     # → cemetery-plan.pdf (5 листов A3, печать через Chromium)
```

### Как устроена отрисовка

Каждое захоронение рисуется отдельным объектом: оградка участка, насыпь
с тенью, надгробие. Внутри участка могилы раскладываются полосами вдоль
короткой стороны по числу номеров — семейный участок на 3 могилы
выглядит как три могилы, а не один прямоугольник.

Номера всегда горизонтальные (поворот участка компенсируется), под
текстом светлая подложка. Чтобы номера не наезжали, план разрезан на
4 сектора вдоль главной оси полосы захоронений (~67 участков на лист,
масштаб 18–24 px/м). Широкие секторы печатаются альбомно.

Грабли, на которые уже наступили:
- при склейке нескольких SVG в один HTML **id обязаны быть уникальными**,
  иначе `clipPath` и градиенты берутся с чужого листа;
- обособленные участки (дальше 25 м от массива) исключаются из кадровки
  сектора, иначе растягивают лист — сейчас такой один, № 125.
